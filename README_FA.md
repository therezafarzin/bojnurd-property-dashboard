# Bojnurd Property Analytics — نسخه واقعی

این نسخه **Demo نیست**. با زدن دکمه «به‌روزرسانی از دیوار»، آگهی‌های واقعی «فروش آپارتمان» شهر بجنورد دریافت و در SQLite روی خود Mac ذخیره می‌شوند.

## اجرا روی Mac
1. فایل ZIP را Extract کن.
2. وارد پوشه `bojnurd_property_dashboard` شو.
3. روی `start.command` دوبار کلیک کن.
4. اگر macOS برای اجرای بار اول اجازه نداد: Right Click روی `start.command` → `Open`.
5. مرورگر روی `http://127.0.0.1:5050` باز می‌شود.

اولین اجرا دیتابیس خالی است. داخل داشبورد روی **«به‌روزرسانی از دیوار»** بزن. بروزرسانی در پس‌زمینه انجام می‌شود و نوار پیشرفت زنده دارد.

## چه داده‌ای تحلیل می‌شود؟
- فقط شهر بجنورد
- فقط فروش آپارتمان
- قیمت کل و قیمت هر متر
- متراژ، سال ساخت، سن بنا و تعداد اتاق
- پارکینگ، آسانسور و انباری در صورت وجود در داده آگهی
- محله دیوار + گروه محله اصلی
- آگهی‌های جدید، غیرفعال‌شده و تغییر قیمت
- حذف تکراری‌های قوی از آمار اصلی
- حذف Outlierهای قیمتی از Median محله
- Median و IQR (صدک 25 تا 75) برای هر محله
- Median نوسازهای 0 تا 3 سال
- «٪ بازار»: فاصله قیمت هر متر یک فایل از Median همان محله
- ذخیره تاریخچه بازار در `data/market.db`

## محله‌ها
نام محله از خود داده دیوار گرفته می‌شود. برای اینکه محله‌های بزرگ شلوغ نشوند، فقط حالت‌های جهت‌دار محافظه‌کارانه ادغام می‌شوند؛ مثلاً «فردوسی شمالی» و «فردوسی جنوبی» زیر «فردوسی» قرار می‌گیرند. نام دقیق دیوار همچنان کنار هر فایل نگه داشته می‌شود.

## تکراری‌ها
تشخیص تکراری عمداً محافظه‌کارانه است تا دو واحد واقعی یک ساختمان اشتباهی یکی نشوند. برای حذف، قیمت/متراژ/محله/سال/اتاق بررسی می‌شود و سپس شباهت خیلی بالای عنوان+توضیحات یا تصویر یکسان لازم است.

## اولین بروزرسانی چرا طولانی‌تر است؟
لیست آگهی‌ها سریع دریافت می‌شود، اما برای تحلیل درست قیمت هر متر باید متراژ و سن بنا هم کامل باشد. جزئیات آگهی‌ها با نرخ محدود و محافظه‌کارانه خوانده می‌شوند. در بروزرسانی‌های بعدی، جزئیات قبلی Cache است و معمولاً خیلی سریع‌تر می‌شود.

## خروجی CSV
از بالای داشبورد روی `CSV خروجی` بزن. فایل شامل قیمت، محله، متراژ، سن بنا، اختلاف با Median و لینک مستقیم دیوار است.

## نکته فنی مهم
این پروژه برای استفاده شخصی روی `localhost` ساخته شده و از endpointهای عمومی‌ای استفاده می‌کند که وب‌سایت دیوار خودش برای نمایش داده‌ها صدا می‌زند؛ این API رسمی «کنار دیوار» نیست. در نتیجه اگر دیوار ساختار داخلی وب خود را تغییر دهد ممکن است فایل `collector.py` نیاز به بروزرسانی داشته باشد. نرخ درخواست‌ها عمداً پایین نگه داشته شده است.

## فایل‌های اصلی
- `app.py` — وب‌اپ Flask
- `collector.py` — دریافت داده واقعی از دیوار
- `service.py` — بروزرسانی، Cache، تاریخچه و Snapshot
- `analytics.py` — Median / IQR / Outlier
- `dedupe.py` — تشخیص تکراری قوی
- `neighborhoods.py` — گروه‌بندی محافظه‌کارانه محله‌ها
- `money.py` — تبدیل قیمت‌های فارسی
- `data/market.db` — دیتابیس محلی (بعد از اولین اجرا)

## پاک کردن همه تاریخچه
برنامه را ببند، سپس روی `reset_database.command` دوبار کلیک کن و `yes` بنویس.
